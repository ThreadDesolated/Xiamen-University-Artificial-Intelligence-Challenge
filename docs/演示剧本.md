# AutoLab 3 分钟现场演示剧本（初赛版 v0.1）

> 目标：评委在 3 分钟内看到 **"失败 → 归因 → 重规划 → 达标 → 配方迁移 → 复现包"** 的完整闭环。
> 所有数字为设计目标，赛前用实测替换（见第 5 节"数字替换清单"）。

## 0. 演示前 10 分钟检查清单

1. `python -m autolab demo --no-recipe` 本地跑通（约 20–40 秒）；
2. 预跑 3 次生成 `traces/` 与 `reports/`（离线回放兜底就绪）；
3. 录屏一份完整演示（网络/API 异常时直接播）；
4. `python -m autolab serve` 启动面板后端，浏览器打开 trace 页；
5. 语音输入（W2 接入）单独试一次，失败则改文本输入口播。

## 1. 开场（0:00–0:25）

> "高校实验课和科研新手的最大浪费不是算力，而是**重复的试错**：跑一次实验十几分钟，
> 失败了不知道为什么，成功了也说不清为什么。AutoLab 让 Agent 像研究生一样做实验——
> 指标当奖励、失败变归因、成功配方可迁移。给我一句话目标，它还你一个可复现的实验包。"

## 2. 任务一：失败与归因（0:25–1:20）

操作：语音/文本输入 → `T1：把验证准确率做到 0.85 以上，预算 2 分钟`。

现场应看到（面板逐步刷新）：
1. 数据画像：`1000 行 × 8 特征，缺失 5%，类别失衡 3:1`；
2. 首轮方案（模板/LLM）：`零填充 + 最近质心，未标准化`；
3. 首轮结果：`accuracy ≈ 0.7x（未达标）`；
4. 归因卡片：`missing_values_poor_imputation (0.75)`、`class_imbalance (0.80)`、`feature_scale (0.60)`；
5. 重规划：`中位数填充 + 标准化 + logistic_gd(class_weight=balanced)`；
6. 第二轮：`accuracy ≈ 0.9x（达标）`。

口播要点："注意它没有乱猜——每条归因都有数据画像里的证据，修复动作白名单内可执行。"

## 3. 任务二/三：配方迁移与提速（1:20–2:10）

操作：切到 T2（图像）/ T3（时序），一句话下达目标。

现场应看到：`T3 首轮直接检索配方库命中 → 首轮达标`；对比 T1 的 2 轮/耗时，
T3 迭代次数与耗时明显下降（目标 ≈2.4×，以实测为准）。

口播要点："第三个任务不是更简单，而是**经验被复用了**——配方按任务画像检索，跨任务迁移。"

## 4. 收尾：可复现交付（2:10–2:50）

1. 打开 `reports/<run_id>/report.md`：轮次表 + 归因表 + 环境信息；
2. 展示 `reports/<run_id>.zip`：`plan.json / env.json / trace.jsonl / reproduce.ps1`；
3. 展示 trace 面板：每步工具调用、耗时、token 成本（一次实验 0.3–1 元）；
4. 结论句："评审可以直接按 `reproduce.ps1` 复跑，结果一致——复现性是一等交付物。"

## 6. 兜底预案（按顺序触发）

1. API 限流/断网 → 切 `demo`（纯规则闭环）或 `replay` 回放；
2. 现场机器太慢 → 用预录视频 + 本机回放；
3. 面板起不来 → 直接 `python -m autolab demo` 终端演示 + 报告 zip；
4. 语音识别失败 → 文本输入口播（同一流程）。

## 7. 答辩 Q&A 预埋（一句话版）

- **为什么必须是 Agent？**：目标由自然语言给定、动作由模型决策、每步读真实指标并据此重规划，
  单轮脚本给不出"失败→归因→改方案"的轨迹。
- **和 AutoML 的区别？**：AutoML 在固定空间调参；AutoLab 会改数据管线、解释失败、迁移配方。
- **和 AI Scientist 的区别？**：它产论文，我们产**可复现实验包 + 可复用配方**。
- **5 周做得完吗？**：执行内核复用 FLAML/sklearn，Agent 只做规划-归因-复现；2 任务保底 + 1 加分。
