# AutoLab 接口契约（W1 冻结版）

本文件是团队协作的"接口说明书"：模块边界、数据结构、trace 事件、存储表、CLI/HTTP 接口。
**改动以下任一契约前，先在群里同步并同步更新本文件与 `autolab/schemas.py`。**

---

## 1. 分层架构与依赖方向

```
交互层  CLI / Web 面板(SSE) / 语音入口(W2+)
   │
编排层  autolab/agent/  graph.py(主链路) planner.py(规划) attributor.py(归因) prompts.py
   │
执行层  autolab/sandbox/  子进程 + JSON 白名单 + 超时 + 禁网；evaluation/ 负责 5 折评估
   │
反馈层  autolab/profile.py(画像) + evaluation/metrics.py(指标) + tracing/(trace)
   │
沉淀层  autolab/store/ (SQLite: runs/recipes/attributions) + report.py(报告与复现包)
```

依赖方向只能自上而下：`agent → sandbox/evaluation/{datasets,profile,report,store,tracing}`。
`sandbox` 不得 import `agent`（`validate.py` 内部对 `agent.planner.template_plan` 的兜底是
延迟 import，属于唯一例外，见第 6 节）。

## 2. 数据流（一次 run）

```
TaskSpec ─▶ load_dataframe(数据) ─▶ profile_dataframe(画像) ─▶ profile_hash
   │
   ├─ 配方库命中? → plan_from_recipe
   ├─ 否则 LLM 规划? → llm_plan（失败降级）
   └─ 否则 → template_plan（永远可用）
                 │
                 ▼
        validate_or_fallback（非法 → 模板兜底）
                 │
                 ▼
        execute_plan（子进程沙箱，5 折 CV） ─▶ ExperimentResult
                 │
        evaluate_target 达标?
          ├─ 是 → save_recipe + report.export_bundle → done
          └─ 否 → attribute(归因) → save_attribution → replan → 下一轮
                 （最多 max_rounds 轮，默认 3）
```

## 3. 核心数据结构（`autolab/schemas.py`）

### 3.1 TaskSpec（任务配置）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| task_id / name | str | 任务 id / 展示名 |
| task_type | str | `binary_classification` / `multiclass_classification` / `regression` |
| data_path | str | `synthetic:t1` / `.csv` / `.npz`（相对仓库根目录） |
| target | str | 目标列名 |
| metric | str | accuracy/f1_macro（分类）、mae/rmse/r2（回归） |
| threshold / higher_is_better | float / bool | 达标阈值与方向 |
| n_splits / seed / budget_seconds / max_rounds | int | 评估协议与预算 |
| features | list[str] \| null | 指定特征列；null 表示自动推断 |
| notes | str | 备注 |

### 3.2 ExperimentPlan（实验方案，受限动作空间）

```json
{
  "plan_id": "plan_...",
  "ops": [{"op": "impute_median", "params": {}}, {"op": "scale_standard", "params": {}}],
  "model": {"kind": "logistic_gd", "params": {"lr": 0.1, "epochs": 400, "class_weight": "balanced"}},
  "eval": {"n_splits": 5, "seed": 42},
  "source": "template | llm | attribution | recipe | reproduce",
  "notes": ""
}
```

### 3.3 ExperimentResult

`status ∈ {ok, error, timeout, invalid}`、`metrics{name: Metrics}`、`train_metric`、`seconds`、
`error`、`stdout_tail`、`warnings`、`artifacts`。

### 3.4 Attribution（失败归因）

`cause`、`confidence(0-1)`、`evidence`、`fix{add_ops,remove_ops,set_model,set_model_params,reduce_splits}`、
`round_idx`。原因取值见第 5 节，**新增 cause 必须同步更新本文件与归因规则说明**。

### 3.5 TraceEvent

`run_id`、`seq`、`ts`、`node`、`tool`、`input`、`output`、`duration_ms`（见第 4 节）。

## 4. trace 事件契约（`traces/<run_id>/trace.jsonl`）

| node | tool | 关键 output |
| --- | --- | --- |
| load_data | datasets.load_dataframe | n_rows、n_cols |
| profile | profile.profile_dataframe | n_rows/n_features/missing_ratio/target/warnings |
| recipe_hit | store.find_recipe | recipe_id、metric_value |
| plan_fallback | planner.llm_plan | error、fallback=template |
| plan | planner.{template,llm,recipe,reproduce} | 完整 plan |
| plan_invalid | sandbox.validate_plan | errors、fallback_plan_id |
| execute | sandbox.execute_plan | status、metric、mean、train_metric、seconds、passed |
| attribute | attributor.attribute | causes[{cause,confidence,evidence,fix}] |
| replan | attributor.replan | 新 plan |
| export | report.export_bundle | report_md、bundle_path |
| error | - | 异常信息 |
| done | - | status、passed、rounds |

约定：每个 node 一条事件；`seq` 单调递增；同一 run 一条 `done` 收尾（SSE 以此结束）。

## 5. 归因规则（规则库优先，LLM 可补充解释）

| cause | 触发条件 | 修复动作 |
| --- | --- | --- |
| budget_exceeded | status=timeout | 减少折数、降低 epochs |
| execution_failed | status∈{error,invalid} | 人工/LLM 检查后重规划 |
| missing_values_poor_imputation | 缺失>2% 且无 mean/median 填充 | add impute_median、remove impute_zero；弱模型升级 logistic_gd |
| class_imbalance | 失衡比>1.5 且未 balanced | class_weight=balanced；弱模型升级 logistic_gd |
| feature_scale | 未标准化 | add scale_standard |
| overfit | train - val > 0.08 | 提升 l2、降低 epochs |
| underfit | 训练折也低于阈值-0.04 | 升级 logistic_gd + balanced |
| unknown_shortfall | 以上都不命中 | 兜底升级模型 + 标准化 |

## 6. 沙箱契约（`autolab/sandbox/`）

- 入口：`python -m autolab.sandbox.runner --spec <spec.json> --out <result.json>`；
- spec：`{"task": TaskSpec.to_dict(), "plan": ExperimentPlan.to_dict()}`；
- 隔离：子进程、`AUTOLAB_NO_NET=1`（netguard patch socket）、`timeout=max(30, budget_seconds+20)`；
- 结果：`result.json`（ExperimentResult 字段）+ 父进程补充 stdout/stderr 尾部；
- 白名单：`configs/whitelist_ops.json`；`validate_plan` 是唯一校验入口，非法方案必须回退模板。

## 7. SQLite 契约（`autolab.sqlite3`）

| 表 | 关键列 | 用途 |
| --- | --- | --- |
| runs | run_id, task_id, status, rounds, best_metric, plan_json, trace_path | 运行档案 |
| recipes | recipe_id, task_type, profile_hash, plan_json, metric_value | 成功配方（跨任务/跨天复用） |
| attributions | attribution_id, run_id, round_idx, cause, confidence, fix_json | 失败知识库 |

## 8. 报告与复现包（`reports/<run_id>/`）

`report.md`（人读）、`plan.json`、`result.json`、`profile.json`、`env.json`、`manifest.json`、
`trace.jsonl`、`reproduce.ps1|sh`；同目录打 `reports/<run_id>.zip`。

## 9. CLI / HTTP

- CLI：`demo`、`run --task --llm --no-recipe --plan`、`prepare`、`replay`、`serve`、`init-db`、`list`；
- HTTP（`autolab serve`，W3 面板用）：`GET /api/tasks`、`GET /api/runs`、`POST /api/runs`、
  `GET /api/runs/{id}`、`GET /api/runs/{id}/trace?after=N`、`GET /api/runs/{id}/stream`(SSE)、
  `GET /api/runs/{id}/report`、`GET /api/stats`、`GET /api/health`。

## 10. 演进约定

  validate 逻辑不变**，只换执行内核（方案生成侧无感）。
- W3+：编排状态机可迁移 LangGraph，但 trace 事件与 summary 字段保持兼容。
